# Домашнее задание по модулю "Микросервисы и gRPC"

Необходимо реализовать два сервиса: `product-service` и `cart`, и организовать взаимодействие между ними.

## Основное задание

Необходимо имплементировать два сервиса:

1. `product-service` — сервис с информацией о товарах. Предоставляет gRPC API.
2. `cart` — сервис корзины пользователя. Предоставляет REST/HTTP API.

Требования к решению:

1. Написать protobuf контракт сервиса `product-service` (`.proto` файл) — один метод `GetProduct`. Структура запроса и ответа описана ниже, имена сообщений, сервисов и нумерация полей остаются на ваше усмотрение.
2. Состояние обоих сервисов храним in-memory, персистентное хранилище на данный момент не требуется.
3. Товары для `product-service` вычитываются из JSON-файла при старте сервиса.
4. Сервис `cart` при добавлении товара в корзину проверяет существование товара походом в `product-service` по gRPC.
5. Взаимодействие сервисов — через gRPC, публичный API сервиса `cart` — через HTTP.

## Дополнительное задание

1. Добавить метод `ListProducts` в `product-service`, возвращающий список товаров с постраничным выводом.
2. Добавить middleware для логирования HTTP-запросов сервиса `cart`.
3. Добавить swagger в сервис `cart`.

## Спецификация Product-service

Сервис отвечает за хранение информации о товарах. Данные загружаются из файла `products.json` при старте.
Структура записи в файле:

```json
{
    "1076963": {
        "name": "Теория нравственных чувств | Смит Адам",
        "price": 3379
    },
}
```

Контракт сервиса вы описываете сами в `.proto` файле. Метод должен называться `GetProduct`,
имена сообщений и сервисов, а также нумерация полей — на ваше усмотрение. Требования к контракту:

- на вход метод принимает идентификатор товара `sku`;
- в ответе сервис возвращает сам `sku`, наименование `name` и цену `price` товара;
- товар ищется по sku; если товара нет — ошибка `NotFound` (код 5);
- валидация: sku должен быть натуральным числом (больше нуля), иначе — `InvalidArgument` (код 3);
- цена в ответе передается как `int32` (в JSON нет беззнаковых целых, поэтому `int32`;
  внутри своих сервисов, для совместимости их между собой, используйте беззнаковый тип `uint32`).

### GetProduct

Возвращает информацию о товаре по его идентификатору SKU.

**Параметры ошибочных ответов:**

| Сценарий                                         | gRPC код ошибки (HTTP) | Описание                                                           |
|--------------------------------------------------|------------------------|---------------------------------------------------------------------|
| Вызов с нулевым или отрицательным значением sku  | 3 (400)                | Идентификатор товара должен быть натуральным числом (больше нуля)   |
| Товар с указанным sku отсутствует в системе      | 5 (404)                | Информацию можно получить только по существующему товару            |
| Все остальные случаи                             | 13 или 2 (500)         | Проблемы из-за неисправностей в системе                             |


## Спецификация Cart

Идентификатором товара является числовой идентификатор SKU. Каждый пользователь имеет числовой
идентификатор userID. При добавлении в корзину проверяем, что товар существует, с помощью вызова
gRPC метода `GetProduct` сервиса `product-service`.

### Добавить товар в корзину

Метод добавляет указанный товар в корзину определенного пользователя. Один и тот же товар может быть
добавлен в корзину несколько раз, при этом количество экземпляров складывается.

| Метод | URI                            |
|-------|--------------------------------|
| POST  | /user/<user_id>/cart/<sku_id>  |

**Параметры запроса:**

| Параметр | Тип параметра | Тип данных | Пример | Описание                                                         |
|----------|---------------|------------|--------|------------------------------------------------------------------|
| user_id  | query path    | int64      | 1007   | Идентификатор пользователя, в корзину которого добавляется товар |
| sku_id   | query path    | int64      | 2008   | Идентификатор товара, добавляемого в корзину                     |
| count    | body          | uint32     | 12     | Количество товаров, добавляемых в корзину                        |

**Параметры ответа:**

отсутствуют

**Параметры ошибочных ответов:**

| Сценарий                                                                                  | HTTP код ошибки | Описание                                                                |
|-------------------------------------------------------------------------------------------|-----------------|-------------------------------------------------------------------------|
| Добавление валидного SKU для пользователя (user_id) с нулевым или отрицательным значением | 400             | Идентификатор пользователя должен быть натуральным числом (больше нуля) |
| Добавление SKU с нулевым или отрицательным значением                                      | 400             | SKU должен быть натуральным числом (больше нуля)                        |
| Добавление SKU с нулевым или отрицательным количеством (count)                            | 400             | Количество должно быть натуральным числом (больше нуля)                 |
| Добавление несуществующего SKU в корзину                                                  | 412             | SKU должен существовать в сервисе `product-service`                     |
| Все остальные случаи                                                                      | 500             | Проблемы из-за неисправностей в системе                                 |

### Получить содержимое корзины

Метод возвращает содержимое корзины пользователя на текущий момент. Если корзины у переданного
пользователя нет, либо она пуста, следует вернуть 404 код ответа. Товары в корзине упорядочены
в порядке возрастания sku.

| Метод | URI                  |
|-------|----------------------|
| GET   | /user/<user_id>/cart |

**Параметры запроса:**

| Параметр | Тип параметра | Тип данных | Пример | Описание                                                         |
|----------|---------------|------------|--------|------------------------------------------------------------------|
| user_id  | query path    | int64      | 1007   | Идентификатор пользователя, у которого запрашивается корзина     |

**Параметры ответа:**

| Параметр       | Тип данных | Пример                                           | Описание                                     |
|----------------|------------|--------------------------------------------------|----------------------------------------------|
| items[i].sku   | int64      | 2008                                             | Идентификатор товара в корзине пользователя  |
| items[i].name  | string     | "Гречка пропаренная, в пакетиках для варки, 400" | Наименование товара                          |
| items[i].count | uint32     | 10                                               | Количество единиц товара                     |
| items[i].price | uint32     | 16                                               | Стоимость единицы товара в условных единицах |
| total_price    | uint32     | 160                                              | Суммарная стоимость всех товаров в корзине   |

**Пример ответа:**

```json
{
    "items" : [
        {
            "sku": 2958025,
            "name": "Roxy Music. Stranded. Remastered Edition",
            "count": 2,
            "price": 1028
        },
        {
            "sku": 773297411,
            "name": "Кроссовки Nike JORDAN",
            "count": 1,
            "price": 2202
        }
    ],
    "total_price": 4258
}
```

**Параметры ошибочных ответов:**

| Сценарий                                                           | HTTP-код ошибки | Описание                                                                |
|--------------------------------------------------------------------|-----------------|-------------------------------------------------------------------------|
| Запрос корзины с нулевым или отрицательным пользователем (user_id) | 400             | Идентификатор пользователя должен быть натуральным числом (больше нуля) |

## Взаимодействие сервисов

Путь покупки товаров:

- POST <cart_host>/user/{user_id}/cart/{sku_id} — Добавляем товар в корзину (с проверкой товара в product-service).
- GET <cart_host>/user/{user_id}/cart — Получаем состав корзины.

Сервис `cart` при добавлении товара вызывает `product-service.GetProduct` по gRPC:

- для валидации существования товара;
- для получения наименования и цены товара, которые сохраняются в корзине и отдаются в ответе метода `GET /user/<user_id>/cart`.

## Makefile

В рамках данного задания необходимо имплементировать следующие таргеты:

- `run-all` — запускает оба сервиса:
  - `product-service` — разрабатываемый вами сервис с gRPC API
  - `cart` — разрабатываемый вами сервис с HTTP API
- `generate` — генерация .go файлов из proto файлов (используем protoc)

## Ожидаемый результат

- с помощью команды `make run-all` можно запустить оба сервиса
- `product-service` слушает gRPC-запросы на порту 50051
- `cart` слушает HTTP-запросы на порту 8080
- товары загружаются в `product-service` из файла при старте сервиса
- реализованы API-методы
    - product-service: GetProduct (gRPC)
    - cart: POST /user/<user_id>/cart/<sku_id>
    - cart: GET /user/<user_id>/cart
- методы реализуют заявленную бизнес-логику
- методы валидируют запросы и отдают описанные в спецификации коды ошибок
- информация о корзинах пользователей хранится в памяти приложения
- при рестарте приложения состояние системы теряется
